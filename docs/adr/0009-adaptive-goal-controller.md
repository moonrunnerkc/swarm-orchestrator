# 0009. Complete goals through bounded integration repair

**Status:** approved September 13, 2026; implementation tracked separately

Swarm should return a reviewable integrated change whose declared requirements were checked.
The owner approved replacing the fixed-graph product constraint with one deterministic
controller in `src/workers`, reusing `runAgentTask` for bounded jobs. No security exception is
part of this decision.

The exact policy revisions are:

- Invariant 12 makes worker declarations subordinate to the effective controller contract.
  A worker amendment cannot grant itself permission.
- Invariant 13 preserves the negative peer trail and permits bounded typed proposals and
  harness observations, with provenance, base and revision identities. Proposals cannot
  establish acceptance; alternative attempts at one task remain independent.
- Invariant 14 preserves the historical comparator and permits goal-oriented selection only
  after every applicable obligation passes. Its objective is declared, not model judged.
- Invariant 15 retains one initial declaration and permits bounded append-only revisions.
  Requirements, policy, budgets and historical outcomes cannot be erased or weakened.
- The build guide replaces its rejection of a swarm-first product direction with bounded
  adaptive integration and independent final acceptance, without a multi-agent core.

Both agent files carry the same policy through the existing invariant drift check. The
command and architecture descriptions previously differed outside that check; they are now
synchronized to the fuller CLAUDE.md description.

One writer owns integration. Repairs start from its current commit and retain rejected
candidate references. Readiness depends on accepted prerequisites and separate resource
limits. The shared run context exists before planning; recovery reconciles checked journal
intents and effects within the original remaining budget. Ambiguity requires reconciliation.

Regression, goal acceptance, execution trust, evidence integrity and signer trust are distinct.
Ordinary executable acceptance does not require an already-correct reference implementation.
Generated checks record authorship and exposure and are not independent ground truth. The
strict reference/control package and all historical evidence readers remain supported.

This decision authorizes implementation, not an empirical claim of advantage. The six
maintainer development goals and frozen 24-goal, eight-repository paired pilot have separate
exit criteria. Paid models, publication and protected-branch merges require existing authority.

Graph version two makes scope allocation explicit. The pre-planning user scope is distinct from a task's exact writable files. A controller-authorized amendment can allocate another file within that ceiling, and a missing-prerequisite insertion preserves the consumer's original obligations. Neither operation widens the run's permissions or budget. Legacy version-one graphs have no such scope-amendment authority. Ordinary goal commands authorize controller allocation within the workspace; supplied file graphs retain their file ceiling. Task authorship cannot change immutable acceptance artifacts or human-only scope authority.
