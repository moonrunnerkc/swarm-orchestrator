# Decisions

One line per open choice made during the verifier-first rebuild (ADR 0014), with the reason.

- The recovery proposal file was not found on this machine; the rebuild prompt is the sole specification, as that prompt already takes precedence over the proposal.
- Rebuilt from the PR #101 head (cce83b6de), the newest line of history, on branch `rebuild/verifier-first`; `v13-main` is left untouched.
- Uncommitted agent-instruction loading work found in the checkout was preserved on branch `wip/agent-instructions-loading` before the rebuild started.
- `check-caps.mjs` runs as `npm run caps` from Phase 1 and joins `npm run gates` in the commit where it first passes, so every commit stays green as required.
- Phase 1 steps 1.1 to 1.4 landed as one commit: deleting src/eval broke src/select, which broke the CLI, so no smaller cut was green on its own.
- The old agent run path was deleted in the Phase 1 cut instead of being repaired around the deleted layers; `run` is absent until the Phase 2 loop lands.
- Phase 3 (verifier) was built before Phase 2 (loop), so the loop calls the real verifier from its first commit instead of an interim one.
- Research scripts beyond the five named directories, and dated research documents, were archived too: they import the deleted evidence checks and describe retired experiments.
- `.gitignore` was rewritten to the rules that still apply; its unanchored `DECISIONS.md` rule would have hidden this file.
- `scratchpad/` is ignored rather than deleted: it holds the owner's local logs.
- The ignored local research data under campaign/, redteam/ and docs/evidence/ was moved (not deleted) into the archive checkout beside its committed counterparts.
- The scrub regression inputs from fuzz/findings moved to src/evidence/fixtures/scrub-findings because the scrubber survives.
- Three legacy bundles moved to src/fixtures/legacy-bundles so the old-format verifier tests stay real until Phase 3 deletes that format.
- Runtime dependencies cut to smol-toml and zod: the Vercel AI SDK packages and undici go with src/providers, since the new loop speaks the OpenAI-compatible chat API over Node's fetch.
- The policy drift check and instruction sync were deleted in the Phase 1 cut rather than step 1.6: the drift check imported the deleted predicate catalogue.
- src/swarm-verify-boundary.test.ts fell out of the Phase 1 cut with the modules it named; Phase 3 restores the closure rule as a build-time check in the verifier's build.
- Product documentation for removed commands (cli, using, verifying, verify-only, agent, build guide, security coverage, claims, examples, engineering policy) was deleted in the cut; README, integrations and results pages replace it.
- ADRs 0012 and 0013 were archived with 0001 to 0011, so the ADR index is the archive pointer plus 0014 alone.
- The attestation is written as a Sigstore bundle (v0.3) wrapping the DSSE envelope, because cosign 3 verifies blob attestations only from a bundle; `cosign verify-attestation` is for OCI images, so the blob form `cosign verify-blob-attestation --bundle --key --insecure-ignore-tlog` is the cosign check used.
- DSSE signatures carry an empty keyid: cosign's verifier skips a signature whose keyid differs from its own, and DSSE defines keyid as an optional, unauthenticated hint; the bundle's public-key hint carries the SHA-256 fingerprint of the key instead.
- `--sigstore` passes the finished Statement to `cosign attest-blob --statement` for keyless signing, so both signing paths produce the same bundle format.
- The tree subject digest is SHA-256 over `<mode> <sha256> <path>` lines for the tracked files of the resulting tree (submodules excluded), so verify.mjs can recompute it from a plain export without git.
- Checks, the protected-path allowance and held-out commands are read from the base commit, never from the change, so a change cannot rewrite what judges it.
- The held-out run restores every protected path the change touched to its base version before overlaying the sealed files, so edited expectations, deleted assertions and a patched scorer do not reach the held-out result.
- Dependencies for checks in the clean checkout are linked from the workspace (node_modules, .venv) unless swarm.toml names a setup command; the predicate records which was used.
- Exit codes: 0 pass, 1 fail (including protected-path violations and a change that does not apply), 2 an unreadable command line, 4 unmeasured (no checks declared).
- A surviving mutant and uncovered changed lines are reported, not verdict-failing: they measure the tests' strength, not the change's correctness.
- The container isolation backend was deleted with the old gates: checks run on the host in a clean temporary checkout under the built child environment, which needs no Docker daemon and removed the only skipped tests.
- The packed-CLI smoke script was deleted: it drove per-command smoke contracts that no longer exist, and ci.yml runs the gates directly.
- Both binaries share one dispatcher (src/cli-main.ts) and one command list, so `swarm` and `swarm-verify` parse, print help and exit identically; `swarm` adds doctor and run.
- The mutation witness tries comparison, logical, boolean, arithmetic, min/max and numeric-literal operators, then drops a returned value as a last resort, so a changed return of a call is still mutated.
- A sealed set lives under SWARM_HOME (default ~/.swarm)/sealed/<hash of the workspace path>, owner-only, outside every workspace the agent sees.
- Each turn carries at most 10,000 bytes of command output (or verifier failure), keeping the start and the end, which is where errors and summaries are.
- The model protocol is one fenced bash block per reply and a completion marker alone on a line, over the OpenAI-compatible chat API at temperature 0, so any local or hosted endpoint works without tool-calling support.
- Where an endpoint reports no token usage, the token budget counts an estimate (characters / 4) for that turn and the run reports how many turns were estimated.
- The chokepoint was narrowed to the one bash tool: JSON argument decoding, the tool registry and the derivation heuristic went, because with nobody in the loop the heuristic's confirmations could only become refusals of ordinary commands.
- Off-allowlist commands are approved by `--approve auto` or `[agent] approval = "auto"`, asked of a person on a terminal, and refused when nobody is there to ask.
- `run` judges against the commit it started from and writes its final attestation to `.swarm/verify/` in the workspace, carrying the model name and the prompt digest.
- The shell reader now reads heredocs: a body is data for most programs, the program itself for node and python (read by the same inline-program reader as -c and -e), and unreadable for a shell or where an unquoted body would expand a substitution. Before this, body lines were read as commands, so every heredoc file write was refused.
- The policy guard resolves denied roots through symlinks as it does requested paths; before, a denied root under a symlinked directory (macOS /var, /tmp) never matched.
- src/core went with the AI SDK model client; the ledger takes a `now` function instead of a clock object.
- The evaluation runs through Harbor, the official harness for Terminal-Bench 2.0, whose registry also carries SWE-bench Verified: it runs each agent in the task's container and judges with the benchmark's own tests, so one runner serves both suites.
- The frozen lists are the first 100 SWE-bench Verified and first 50 Terminal-Bench 2.0 task names in byte order, taken once from Harbor's swebench-verified@1.0 and terminal-bench@2.0 downloads on 2026-10-29.
- mini-swe-agent and OpenCode run as Harbor's built-in agents; swarm runs through a small Harbor adapter (eval/harbor/swarm_agent.py) that installs this checkout's packed build. All three use the endpoint and model in this repository's swarm.toml [agent].
- Harbor's mini-swe-agent install pulls a litellm release that imports the optional `mcp` package on every completion; eval/harbor/mini_agent.py adds `mcp` to the same tool environment and changes nothing else.
- OpenCode is given the model under a provider named `local`, because it calls the Responses API for a provider named `openai` even when configured for chat completions.
- SWE-bench Verified images are x86_64 only, so the evaluation runs in a separate Colima profile (swarm-eval, vz with Rosetta) with buildx and DOCKER_DEFAULT_PLATFORM=linux/amd64; the default Colima VM is untouched.
- A trial the benchmark's tests never judged (a harness error) is recorded with pass null and reported under Tasks but not Judged; pass@1 is over judged trials and both counts are printed.
- The tamper evaluation counts a patch as flagged when the verdict is anything but pass; precision with nothing flagged would be reported as n/a, not zero.
- The 10 MB fresh-clone limit is measured on a depth-1 clone (1.4 MB at the end of the rebuild): the full history still carries the archived evidence, and rewriting published history would be destructive and was not asked for.
- OpenCode is pinned to 1.14.48 in the evaluation: Harbor installs the latest (1.19.5), which never exits after its final turn, and 1.14.48 is the version earlier comparisons ran.
