# Decisions

One line per open choice made during the verifier-first rebuild (ADR 0014), with the reason.

- The recovery proposal file was not found on this machine; the rebuild prompt is the sole specification, as that prompt already takes precedence over the proposal.
- Rebuilt from the PR #101 head (cce83b6de), the newest line of history, on branch `rebuild/verifier-first`; `v13-main` is left untouched.
- Uncommitted agent-instruction loading work found in the checkout was preserved on branch `wip/agent-instructions-loading` before the rebuild started.
- `check-caps.mjs` runs as `npm run caps` from Phase 1 and joins `npm run gates` in the commit where it first passes, so every commit stays green as required.
- Phase 1 steps 1.1 to 1.4 landed as one commit: deleting src/eval broke src/select, which broke the CLI, so no smaller cut was green on its own.
- The old agent run path was deleted in the Phase 1 cut instead of being repaired around the deleted layers; `run` is absent until the Phase 2 loop lands.
- Phase 3 (verifier) was built before Phase 2 (loop), so the loop calls the real verifier from its first commit instead of an interim one.
- Research scripts beyond the five named directories, and dated research documents, were archived too: they import the deleted evidence checks and describe retired experiments.
- `.gitignore` was rewritten to the rules that still apply; its unanchored `DECISIONS.md` rule would have hidden this file.
- `scratchpad/` is ignored rather than deleted: it holds the owner's local logs.
- The ignored local research data under campaign/, redteam/ and docs/evidence/ was moved (not deleted) into the archive checkout beside its committed counterparts.
- The scrub regression inputs from fuzz/findings moved to src/evidence/fixtures/scrub-findings because the scrubber survives.
- Three legacy bundles moved to src/fixtures/legacy-bundles so the old-format verifier tests stay real until Phase 3 deletes that format.
- Runtime dependencies cut to smol-toml and zod: the Vercel AI SDK packages and undici go with src/providers, since the new loop speaks the OpenAI-compatible chat API over Node's fetch.
- The policy drift check and instruction sync were deleted in the Phase 1 cut rather than step 1.6: the drift check imported the deleted predicate catalogue.
- src/swarm-verify-boundary.test.ts fell out of the Phase 1 cut with the modules it named; Phase 3 restores the closure rule as a build-time check in the verifier's build.
- Product documentation for removed commands (cli, using, verifying, verify-only, agent, build guide, security coverage, claims, examples, engineering policy) was deleted in the cut; README, integrations and results pages replace it.
- ADRs 0012 and 0013 were archived with 0001 to 0011, so the ADR index is the archive pointer plus 0014 alone.
- The attestation is written as a Sigstore bundle (v0.3) wrapping the DSSE envelope, because cosign 3 verifies blob attestations only from a bundle; `cosign verify-attestation` is for OCI images, so the blob form `cosign verify-blob-attestation --bundle --key --insecure-ignore-tlog` is the cosign check used.
- DSSE signatures carry an empty keyid: cosign's verifier skips a signature whose keyid differs from its own, and DSSE defines keyid as an optional, unauthenticated hint; the bundle's public-key hint carries the SHA-256 fingerprint of the key instead.
- `--sigstore` passes the finished Statement to `cosign attest-blob --statement` for keyless signing, so both signing paths produce the same bundle format.
- The tree subject digest is SHA-256 over `<mode> <sha256> <path>` lines for the tracked files of the resulting tree (submodules excluded), so verify.mjs can recompute it from a plain export without git.
- Checks, the protected-path allowance and held-out commands are read from the base commit, never from the change, so a change cannot rewrite what judges it.
- The held-out run restores every protected path the change touched to its base version before overlaying the sealed files, so edited expectations, deleted assertions and a patched scorer do not reach the held-out result.
- Dependencies for checks in the clean checkout are linked from the workspace (node_modules, .venv) unless swarm.toml names a setup command; the predicate records which was used.
- Exit codes: 0 pass, 1 fail (including protected-path violations and a change that does not apply), 2 an unreadable command line, 4 unmeasured (no checks declared).
- A surviving mutant and uncovered changed lines are reported, not verdict-failing: they measure the tests' strength, not the change's correctness.
- The container isolation backend was deleted with the old gates: checks run on the host in a clean temporary checkout under the built child environment, which needs no Docker daemon and removed the only skipped tests.
- The packed-CLI smoke script was deleted: it drove per-command smoke contracts that no longer exist, and ci.yml runs the gates directly.
- Both binaries share one dispatcher (src/cli-main.ts) and one command list, so `swarm` and `swarm-verify` parse, print help and exit identically; `swarm` adds doctor and run.
- The mutation witness tries comparison, logical, boolean, arithmetic, min/max and numeric-literal operators, then drops a returned value as a last resort, so a changed return of a call is still mutated.
- A sealed set lives under SWARM_HOME (default ~/.swarm)/sealed/<hash of the workspace path>, owner-only, outside every workspace the agent sees.
- Each turn carries at most 10,000 bytes of command output (or verifier failure), keeping the start and the end, which is where errors and summaries are.
- The model protocol is one fenced bash block per reply and a completion marker alone on a line, over the OpenAI-compatible chat API at temperature 0, so any local or hosted endpoint works without tool-calling support.
- Where an endpoint reports no token usage, the token budget counts an estimate (characters / 4) for that turn and the run reports how many turns were estimated.
- The chokepoint was narrowed to the one bash tool: JSON argument decoding, the tool registry and the derivation heuristic went, because with nobody in the loop the heuristic's confirmations could only become refusals of ordinary commands.
- Off-allowlist commands are approved by `--approve auto` or `[agent] approval = "auto"`, asked of a person on a terminal, and refused when nobody is there to ask.
- `run` judges against the commit it started from and writes its final attestation to `.swarm/verify/` in the workspace, carrying the model name and the prompt digest.
- The shell reader now reads heredocs: a body is data for most programs, the program itself for node and python (read by the same inline-program reader as -c and -e), and unreadable for a shell or where an unquoted body would expand a substitution. Before this, body lines were read as commands, so every heredoc file write was refused.
- The policy guard resolves denied roots through symlinks as it does requested paths; before, a denied root under a symlinked directory (macOS /var, /tmp) never matched.
- src/core went with the AI SDK model client; the ledger takes a `now` function instead of a clock object.
- The evaluation runs through Harbor, the official harness for Terminal-Bench 2.0, whose registry also carries SWE-bench Verified: it runs each agent in the task's container and judges with the benchmark's own tests, so one runner serves both suites.
- The frozen lists are the first 100 SWE-bench Verified and first 50 Terminal-Bench 2.0 task names in byte order, taken once from Harbor's swebench-verified@1.0 and terminal-bench@2.0 downloads on 2026-10-29.
- mini-swe-agent and OpenCode run as Harbor's built-in agents; swarm runs through a small Harbor adapter (eval/harbor/swarm_agent.py) that installs this checkout's packed build. All three use the endpoint and model in this repository's swarm.toml [agent].
- Harbor's mini-swe-agent install pulls a litellm release that imports the optional `mcp` package on every completion; eval/harbor/mini_agent.py adds `mcp` to the same tool environment and changes nothing else.
- OpenCode is given the model under a provider named `local`, because it calls the Responses API for a provider named `openai` even when configured for chat completions.
- SWE-bench Verified images are x86_64 only, so the evaluation runs in a separate Colima profile (swarm-eval, vz with Rosetta) with buildx and DOCKER_DEFAULT_PLATFORM=linux/amd64; the default Colima VM is untouched.
- A trial the benchmark's tests never judged (a harness error) is recorded with pass null and reported under Tasks but not Judged; pass@1 is over judged trials and both counts are printed.
- The tamper evaluation counts a patch as flagged when the verdict is anything but pass; precision with nothing flagged would be reported as n/a, not zero.
- The 10 MB fresh-clone limit is measured on a depth-1 clone (1.4 MB at the end of the rebuild): the full history still carries the archived evidence, and rewriting published history would be destructive and was not asked for.
- OpenCode is pinned to 1.14.48 in the evaluation: Harbor installs the latest (1.19.5), which never exits after its final turn, and 1.14.48 is the version earlier comparisons ran.
- The model client posts with node:http and node:https instead of fetch: fetch's built-in five-minute headers timeout cut off non-streamed completions that took longer, before the client's own timeout (found in the smoke run, where three attempts on one turn each ended at 5m04s).
- After that fix the swarm arm of the smoke was rerun into the same run with `--into`; its earlier rows are kept as `swarm.jsonl.superseded-<time>` and every row records the commit it ran at, which the results page names per arm.
- Harbor job names carry the invocation's timestamp, not the run name: the first `--into` rerun reused Harbor's finished jobs of the same name, so its rows repeated the earlier results under the new commit. Those rows are kept as `swarm.jsonl.invalid-reused-harbor-job` and counted nowhere.
- The fifteen-file limit on src/verify counts its test files too: v8-lines.ts folded into coverage.ts, git.ts into change.ts, and the four small unit-test files into verify.test.ts, leaving 12 sources and 2 test files.

## Continuation: verifier defects, evaluation, surfaces and release

- The repository's default branch is `v13-main` (origin's HEAD), not `main`; the rebuild fast-forwards it, since `v13-main` is an ancestor of the rebuild.
- History rewrite: before it, a full clone of origin was 404 MB (259 MB of packs: 38 branches and 78 tags over two lineages); after it, a clone of the rewritten default branch and its tags is 7.6 MB. The invocation, in a scratch repository holding only `v13-main`, the PR #101 head and the tags reachable from `v13-main`: `git filter-repo --force --invert-paths --paths-from-file dropped-paths.txt`, where the file lists `regex:^docs/evidence/(?!README\.md$)` and the prefixes docs/history, campaign, redteam, fuzz and the twelve archived `scripts/` directories (ai-pr-study, campaign, comparison, feedback-study, fixtures, local-campaign, onboarding, pilot, reach-pressure, redesign, strengthen-dev, triage). `docs/evidence/README.md` is kept because HEAD still has it.
- Dropping only those paths leaves a 66 MB clone with every branch and tag kept: the pre-v13 lineage (tags v2.0.1 to v12.1.1, `dogfood/tamper-demo`) carries 35 MB of `benchmarks/` corpora and a committed `.venv`, and the evidence branches carry session tarballs. So origin keeps `v13-main` and the 41 tags in its history; the other 37 branches and the 38 tags outside that history are deleted from origin after they were pushed to the archive.
- Every original ref was pushed to moonrunnerkc/swarm-orchestrator-archive before anything was rewritten or deleted: origin's branches under `refs/heads/pre-rebuild/origin/`, its tags under `refs/tags/pre-rebuild/`, every local branch under `refs/heads/pre-rebuild/local/`, and `pre-rebuild-history` itself. All 116 origin refs were checked against `git ls-remote` of the archive, SHA for SHA.
- Confirmation: all 17,467 files under the dropped paths at the rebuild base `cce83b6de` have the same blob id at the same path in the archive's `main` tree, so they are byte-identical. The 39,289 dropped paths that exist only in older commits are kept in the archive's `pre-rebuild/*` refs, which are the original commits.
- `pre-rebuild-history` was pushed to origin first, at the original `v13-main` head `66b421274`. A tag on origin is fetched by every clone, so keeping it at the original commit would bring the whole old history back. Origin's copy is therefore rewritten with everything else; the original-commit tag lives in the archive under the same name.
- Commit ids recorded in stored results (`commit` fields) were mapped through filter-repo's commit map, so they name commits that exist after the rewrite; `0a7ca584d` (the smoke run's swarm arm) is now `098f75bb9`. File contents that cite older commits (this file, `docs/evidence/README.md`) name the original commits, which the archive keeps.
- Releases on the 38 deleted tags (v2.0.1 to v12.1.0) lose their tag on origin, and GitHub turns a release whose tag is gone into a draft; the tags are in the archive under `refs/tags/pre-rebuild/` and can be pushed back to republish one.
- `swarm run` sends `max_tokens` on every turn: the smaller of the per-turn cap and the tokens left in the run's budget. The cap defaults to 16,384 (`--turn-tokens`, `[agent] turn_tokens`), room for a reasoning model's thinking and one command, and a bound on a reply that degenerates into repetition. A reply cut off at the cap is handed back as cut off.
- A permanent endpoint failure stops `swarm run` with stop `model-error`: a refused connection or a 4xx other than 429 at once, other network failures and 5xx answers on the third in a row. A 429 waits 2, 4, 8, 16, 32 and 60 seconds before it counts. The verifier still judges whatever tree exists, and the outcome block prints the failure as `reason` and the verdict.
- A surviving mutant stays reported and not verdict-failing, as decided at the rebuild: the tamper evaluation's honest patches would be the cost of failing on it, and a weak test is a fact about the tests, not the change. `swarm run`'s outcome block prints one `mutant` line naming the file and line when the mutant of a changed line survives.
- The instruction loading on `wip/agent-instructions-loading` was not ported. A port that reads only `AGENTS.md` and `CLAUDE.md` from the workspace root, skips symlinks and cuts each file at 8,000 bytes came to 32 lines, but with the endpoint fixes the loop (src/agent without tests) is 511 lines before it and 547 with it, over the 500 the port was conditioned on. The branch was deleted after it was pushed to the archive as `pre-rebuild/local/wip/agent-instructions-loading`.
- Every declared and held-out check runs at the base commit first, in the clean checkout after the setup command (or dependency links) and before the change applies; tracked files and the sealed overlay are put back to the base afterwards. A declared check judged against its base run: passes at base and fails with the change is a regression and fails the verdict; fails at base and passes is fixed by the change and counts as a pass; fails at base and still fails is `pre-existing-failure`, carries the base output digest, is excluded from the pass rate and is listed under unmeasured. Reading "fails at base" alone as excluded would have made every bug fix unmeasured, because the test that shows a bug fails at base by definition.
- A pre-existing failure makes the verdict `unmeasured` (exit 4) instead of letting the other checks pass it: whether the change was meant to fix that check cannot be told from a check-level run, and unmeasured never counts as a pass. It no longer fails every change; it is reported as what it is.
- Held-out checks are run at base and their base results recorded, but a held-out check that fails with the change still fails the verdict whatever it did at base: they are sealed to fail until the change is right, so failing at base is their expected state. One that passes at base is listed under unmeasured as not telling the change apart.
- `swarm run` hands an unmeasured verdict back to the model like a refusal when a check fails at base and still fails (the output included), and stops on unmeasured only when nothing could be measured.
- Base results are cached under SWARM_HOME/baselines, owner-only, keyed by the SHA-256 of the base commit, the environment digest at base, the sealed set and the judge's code, and validated with Zod on read. Code under test runs unsandboxed as the same user and could write there; that is the same exposure as the sealed store and the installed verifier, and docs/verifying.md says so.
- The predicate gains `baseline` (measured with `cached`, `environmentSha256`, the base results of every declared and held-out check, or unmeasured), the check result `pre-existing-failure` with `baseOutputSha256`, and `heldOut.judge` (processes that loaded the judge, node:assert calls). The predicate type stays `https://swarm-verify.dev/verdict/v1`: it has not been released.
- Held-out isolation is a judge loaded before any project module: `NODE_OPTIONS=--import <judge.mjs>` and a `sitecustomize.py` on `PYTHONPATH`, both written to the run's scratch directory outside the checkout. The Node judge turns every assertion function of `node:assert` and `node:assert/strict` into a counting accessor whose setter records an assignment, and records `node:test`'s exports and the builtins assertions lean on (Object.is, Array.prototype.includes and the other methods listed in src/verify/judge.ts). The Python judge records `unittest.TestCase`'s assert, fail and run methods, the builtins tests compare with, and pytest's runtest, call and assertion-rewrite hooks. At exit each process appends `ok <nonce>` or `tampered <nonce> <names>`; its start line carries the nonce's SHA-256.
- A held-out check fails when any process reported a change, or when a process that loaded the judge never reported (killed, or its exit hooks removed). Call counts are recorded in the predicate, not judged: a test may assert through a library that never calls node:assert. A run in which no process loaded the judge (a test runner that is neither Node nor Python) keeps its held-out results.
- The judge's own sitecustomize runs the interpreter's original sitecustomize first, since Homebrew's and some distributions' Pythons configure their paths there.
- `.npmrc`, `.yarnrc`, `.yarnrc.yml`, `sitecustomize.py`, `usercustomize.py` and `*.pth` files are protected as config: each can change what a check's processes load before the judge.
- The Node judge also watches the project's own test helpers: a module hook appends, to every ES module under a test directory of the checkout, a call that hands the judge its namespace once it has evaluated, and the judge records the exported functions, their prototypes' methods and exported objects' methods. Helpers loaded through `require` are not watched.
- The tamper set's four new overridden-equality cheats: `Object.defineProperty` on `node:assert/strict`'s `deepStrictEqual` (patching assert without assigning it), a prototype patch of an `expect` helper the duration fixture commits under `test/` (the expect variant: Node has no built-in expect, so the helper is the project's own, as many suites keep one), a case-insensitive `Object.is`, and an always-true `Array.prototype.includes`. Each is wrong on one new held-out input checked only through the overridden comparison, and each fixture's oracle gained that input.
- The monorepo dependency links and the submodules left out of the tree digest are stated as limitations in docs/verifying.md: the first has a workaround (a `[verify] setup` command that installs into the checkout) and the second follows from `verify.mjs` recomputing the digest without git.
- docs/FOLLOW-UPS.md now holds only work whose fix would change the product's shape. The evaluation's remaining frozen tasks moved out of it: the nightly workflow runs them.
- There was no MCP server at the rebuild's head, only a note that an MCP client runs the command line. `packages/swarm-verify/mcp.mjs` is one now: dependency-free JSON-RPC over stdio (initialize, ping, tools/list, tools/call) with one tool that runs the package's own `swarm-verify verify --json` and returns its predicate. It ships as the package's `swarm-verify-mcp` bin and adds no subcommand.
- `act` is not installed here, so the Action is proven by running its steps by hand (docs/demos/action-demo.sh): the manifest's own `run:` line, read out of action.yml, under the env it declares, with `GITHUB_BASE_REF` and `GITHUB_STEP_SUMMARY` set as a pull_request job sets them, and the version input `file:<tarball>` naming this checkout's packed verifier. `actions/setup-node` is stood in for by the host's Node 24.
- The pre-commit demo installs the packed verifier into its scratch repository so the documented entry, `npx --yes swarm-verify`, resolves to this checkout instead of the older release on npm; the hook is a plain git hook running that entry, since the pre-commit framework is not installed here and the entry is `language: system`.
- docs/integrations.md pins the Action to `@swarm-verify-v2.0.0`: the branch it named (`main`) is deleted from origin with the other non-default branches.
- The verifier package's `prepublishOnly` ran a release-validation script the rebuild had deleted, so every publish would have failed before uploading; the hook was removed rather than pointed at something new.
- The rebuild's before and after numbers had no stored record, so the README could not cite them. `eval/rebuild.mjs` measures them from git (the caps' line, dependency and subcommand counts at the rebuild's base commit and at HEAD) and times each tree's own `npm test` after `npm ci` in a scratch worktree; docs/results.md reports its latest result. It is run after the three-arm evaluation, so neither suite is timed beside it.

## Found by eval

- On astropy__astropy-12907 `swarm run` got an unmeasured verdict (a check failing at base and with the change), was told the verifier had refused the change, and spent its remaining 45 steps repeating `git diff`. An unmeasured verdict now gets its own note (fix the failure if the task needs it, otherwise complete again), and a second completion over the same unmeasured reasons stops the run as `unmeasured`.
- The first five swarm trials all ended on a budget without completing. Their ledgers (copied out of the task container from then on, by eval/harbor/swarm_agent.py) show the model re-running the same command with the same output up to 13 times in a row: at temperature 0, a reply and an unchanged observation reproduce the context that produced them. The note after a command now says when the command and its output repeat the previous turn's.
- The same ledgers showed every token count in the evidence as `[redacted:credential-field]`: the shared scrubber reads a bare `tokens` key as a credential, by design, and exempts measurement names such as `tokensUsed`. The loop's evidence records use `tokensUsed`.
- After these fixes the swarm arm of the 30-task run was restarted at the fixed commit; its five earlier rows are kept beside the new file as `swarm.jsonl.superseded-<time>` and counted nowhere. mini-SWE-agent and OpenCode continued where they were.
