# Migrating from v6 to v7

v7.0.0 is a scope-rewrite release. Several v6 surfaces were removed
rather than deprecated. This guide covers the breaking changes that
ship in v7.0.0 — what the failure looks like, why it happened, and the
migration path (or lack thereof) for each.

If a v6 invocation appears to work but produces unexpected results,
that is a bug; report it. The breaking changes documented here all
fail loudly.

## Persona collapse → worker / reviewer

**What changed.** v6 had six personas defined under `agents/` and
referenced by `config/agents/*.yaml`: `BackendMaster`,
`FrontendExpert`, `TesterElite`, `SecurityAuditor`, `DevopsPro`, and
`IntegratorFinalizer`. v7 collapsed all six to two: `worker` and
`reviewer`.

**Failure mode.** Plans saved with v6 agentName fields fail validation
on load. Custom agent profiles in `config/agents/*.yaml` referencing
the old persona names are not resolved.

**Migration mapping.**

| v6 persona | v7 role |
|---|---|
| `BackendMaster` | `worker` |
| `FrontendExpert` | `worker` |
| `TesterElite` | `worker` |
| `SecurityAuditor` | `worker` |
| `DevopsPro` | `worker` |
| `IntegratorFinalizer` | `reviewer` |

The role distinction is now structural, not topical. A `worker` step
makes changes; a `reviewer` step is read-only. Topic specialization
(security review, accessibility audit, etc.) is now expressed via the
reviewer step's task text and its `--policy` flag, not via separate
agent profiles.

**Code path for the migration.** `src/types/plan.ts` now exports
`WorkerStep | ReviewerStep | RoleStep`. Plan-load validation rejects
plans whose `agentName` is not one of `worker` or `reviewer`. Plan
files generated by v7 emit only the new role names.

## Removed modules

The following modules were removed in the v7 overhaul. Importing from
their paths fails at load time.

| Removed module | Symptom on v6-style import | Replacement |
|---|---|---|
| `src/fleet-executor.ts` | `Cannot find module './fleet-executor'` | None. Wave-of-N parallel fleet execution removed; the static dependency analyzer (`src/scheduling/dependency-analyzer.ts`) decides parallelism. |
| `src/mcp-server.ts` | `Cannot find module './mcp-server'` | None. The MCP/JSON-RPC stdio surface is gone; the orchestrator's only IPC is the agent-CLI subprocess interface. |
| `src/plan-storage.ts` | `Cannot find module './plan-storage'` | Plan persistence is now per-call via `src/plan-files.ts`. The cache-and-replay surface is removed. |
| `src/critic-reviewer.ts` | `Cannot find module './critic-reviewer'` | None. The reviewer-step pattern in the falsification battery covers reviewer-pass intent without the governance-wave overhead. |

If your project imports any of these, the import errors at the first
`require()` / `import` and there is no shim. Rewrite the call site.
For most consumers, the refactor is "drop the import; the orchestrator
already handles this internally."

## Removed flags

The following CLI flags were removed. Invoking them produces an
"Unknown flag" error from the CLI dispatcher, not silent ignore.

| Removed flag | Resolution |
|---|---|
| `--fleet` | None. Wave-of-N parallel mode removed. The static dependency analyzer decides parallelism on every run. |
| `--team-size <n>` | None. Same removal as `--fleet`. |
| `--plan-cache <path>` | None. Plan caching removed; every run produces a fresh plan. |
| `--replay <run-id>` | None. Run replay removed. |

## Quality gates demoted to advisory

**What changed.** In v6, quality-gate failures could block the merge
path under certain configurations. In v7, the nine built-in gates
(`scaffoldDefaults`, `duplicateBlocks`, `hardcodedConfig`,
`readmeClaims`, `testIsolation`, `runtimeChecks`, `accessibility`,
`testCoverage`, `testFileProtection`) are advisory. Findings appear in
the run report and feed the composite score, but they do not roll back
the merge.

**Failure mode.** None visible. The orchestrator continues to run; the
final-quality-gates report is generated as expected; merges that v6
would have rolled back now succeed in v7.

**Migration path.** CI that depended on gate-failure-blocks-merge
behavior should switch to composite-score thresholds in
`.swarm/gates.yaml`:

```yaml
verification:
  composite:
    threshold: 0.7
    weights:
      cheatDetector: 0.4
      propertyGate: 0.4
      attestation: 0.2
    advisoryGatePenalty: 0.02
```

The composite score gate is still hard: a run scoring below
`composite.threshold` does not produce a signed attestation, and
downstream consumers reading `swarm attest verify <commit>` will see
the verification fail.

## Web dashboard runtime dependencies trimmed

**What changed.** v6 shipped a richer Ink-based TUI with several
React/Ink runtime dependencies. v7 trimmed the UI surface; the
dashboard component (`src/dashboard.tsx`) is still present but the
dependency surface is smaller.

**Failure mode.** Projects that depended on the orchestrator's
transitive React/Ink imports (e.g., custom UI integrations rendering
inside the dashboard frame) report missing-dep errors at runtime.

**Migration path.** Reinstall whatever Ink/React deps your project
needs as your own direct dependencies. The orchestrator no longer
re-exports them.

## Plan file schema changes

**What changed.** v7 plan files are slightly more constrained:

- `agentName` must be `worker` or `reviewer` (see persona collapse
  above).
- New optional field: `metadata.totalSteps` is computed and emitted by
  the planner; v6 plan files without this field load fine but new
  plans always include it.

**Migration path.** v6 plan files saved with the old persona names
need to be regenerated or hand-edited. Plan files saved with v6
generic schema (worker/reviewer or non-persona names) load
unchanged.

## SWE-bench harness changes

If you were running `benchmarks/swe-bench/evaluation-scripts/run_swebench.py`
under v6:

- The harness now passes `--task-type swebench` to the orchestrator,
  which bypasses the heuristic keyword classifier and uses the
  two-step worker/reviewer plan shape. v6's three-step bug-fix plan
  is gone.
- The synthesizer's model ID changed format (`claude-sonnet-4.6` →
  `claude-sonnet-4-6` to match the Claude CLI's accepted model-ID
  format).
- The synth eval's structural validator was dropped. Synthesizer
  output goes directly to the test runner; the runner's exit code
  is the only structural gate.

If you have custom analysis scripts reading
`benchmarks/swe-bench/results/*.json`, the per-task fields are mostly
stable: `instance_id`, `resolved`, `synth_eval`, `property_eval`,
`tests`, `run`. Two notes:

- `synth_eval.testFilePath` is now at the worktree root with prefix
  `swarm-synth-attempt-N-...` instead of `.swarm/synthesized-tests/...`.
  The candidate file is also removed after the eval finishes; the
  test source is preserved on the JSONL record for post-hoc inspection.
- `synth_eval.basePass` and `goldPass` should be read as advisory on
  legacy codebases per [`docs/known-gaps.md`](known-gaps.md). Layer 2
  (`tests.passed`) is the authoritative resolution gate.

## Things that did not change

- The `swarm run --goal` entry point still exists and still uses the
  heuristic keyword classifier. The classifier's bug-fix-prose
  misroute (documented in `docs/known-gaps.md`) was a pre-v7 issue
  that v7 surfaces but does not fix; the SWE-bench bypass is the
  v7.0.0 workaround for that specific use case.
- Orchestrator-side environment-variable handling
  (`SWARM_SKIP_OUTCOME_TEST_EXEC`, `SWARM_BIN`, `SWEBENCH_*`) is
  unchanged.
- Run artifact layout (`runs/<execution-id>/{session-state.json,
  metrics.json, cost-attribution.json, steps/, verification/}`) is
  unchanged.
- The `swarm attest verify <commit>` flow is unchanged. Existing v6
  attestations on commits in your history are still verifiable; v7
  produces attestations in the same format.

## If something silently does the wrong thing

This guide covers loud breakages. If a v6 workflow appears to run
under v7 but produces unexpected output, that is a bug, not a
documented migration. File an issue with:

- The exact CLI invocation used.
- The expected output (under v6).
- The observed output (under v7).
- The run ID from `runs/<execution-id>/` if available.

v7.0.0 explicitly fails loudly on the breaking changes above. Silent
behavior change is a regression to fix in v7.0.1, not a migration
note to add here.
