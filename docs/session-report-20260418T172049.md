## 1. P0 resolution — copilot auth failure in `swarm demo demo-fast`

**Root cause category: (a) env var propagation.**

The orchestrator's Node process loads `.env` at startup ([src/cli.ts:79](../src/cli.ts#L79)).
On this host, `.env` set `GITHUB_TOKEN=github_pat_...` for unrelated GitHub
API use (MCP server, secret redactor). Copilot CLI's auth selection order
prefers env-based tokens (`COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, `GITHUB_TOKEN`)
over its keyring OAuth. The PAT in `.env` does not have the "Copilot
Requests" permission, so every spawn 401'd with
`Error: Authentication failed (Request ID: ...)` in ~3 seconds. Manual
`copilot -p` from a shell worked only because my shell did not have
GITHUB_TOKEN set.

Evidence path that nailed it:
- `docs/debug/env-fail.json` vs `docs/debug/env-ok.json` → diff in
  `docs/debug/env-diff.txt` — `GITHUB_TOKEN` is the one copilot-relevant
  delta (PAT value redacted post-commit; see commit `06475a8`).
- `~/.copilot/logs/process-1776544274693-218894.log` line:
  `Error loading models: Error: 401 "checking third-party user token:
  unauthorized: Personal Access Token does not have 'Copilot Requests'
  permission"`
- Direct reproduction outside the orchestrator:
  `GITHUB_TOKEN=$(grep ^GITHUB_TOKEN= .env | cut -d= -f2-) copilot -p "say hello"`
  → immediate auth failure.

**Fix commits:**
- `5309883 fix(copilot-adapter): scrub GITHUB_TOKEN/GH_TOKEN/COPILOT_GITHUB_TOKEN from spawn env`
- `06475a8 security: redact live PAT from P0 evidence artifacts`

The fix adds `scrubCopilotHostileTokens(env)` in
[src/adapters/copilot-adapter.ts](../src/adapters/copilot-adapter.ts) which
deletes those three keys from the child env before spawn. The same
scrubbing runs on the legacy `runCommand` path in
[src/session-executor.ts](../src/session-executor.ts). A user who has a
Copilot-capable PAT can opt back in with `SWARM_USE_ENV_GITHUB_TOKEN=1`.
Covered by new tests in [test/adapters.test.ts](../test/adapters.test.ts).

**Bisect harness output:** `docs/debug/auth-bisect-run1.log` and
`docs/debug/auth-bisect2-run1.log`. Every layer L0–L6 succeeded under the
orchestrator's spawn env overlay, which initially threw me. The layer that
finally reproduced was "real orchestrator path" — which turned out to be
the env inheritance, not any of the L1–L6 differences.

## 4. P3 parseRequestCount fix

Four commits, split for isolated review:
- `51ba656 test(p3): add real Copilot CLI stderr transcript fixtures for parseRequestCount`
- `abf3fab fix(p3): parse Copilot "Requests N Premium" stderr marker; stop returning a fake 1`
- `09df430 test(p3): fixture-driven tests for parseCopilotRequestCount`
- `acc46dd test(p3): capture demo-fast run proving parser produces honest per-step counts`

**Before the fix:** `(result as any).premiumRequestsConsumed` read in
`swarm-orchestrator.ts:1611` was always `undefined` because no code path
set it. Cost recorder fell through to the `1` literal for every copilot
step. The Claude Code `parseRequestCount` existed but always returned 1 on
non-empty stdout.

**After the fix:** a new
[`parseCopilotRequestCount`](../src/adapters/copilot-adapter.ts) in
copilot-adapter.ts extracts the count from Copilot's stderr
`Requests N Premium` summary line. `CopilotAdapter.spawn` now returns
`premiumRequestsConsumed` in its `AgentResult`. `SessionResult` has a new
`premiumRequestsConsumed` field populated in `executeViaAdapter` and in
the non-copilot adapter path. `swarm-orchestrator` now reads
`result.sessionResult?.premiumRequestsConsumed`. Claude Code's
`parseRequestCount` honestly returns `undefined`.

Before/after on the same run (demo-fast, single step, stderr fixture):
- **Before:** synthetic 1 regardless of what Copilot printed.
- **After:** `parseCopilotRequestCount("Requests  1 Premium (8s)") === 1`
  — still 1, but now because the parser matched the real line. Other
  fixtures: `"Requests  4 Premium (112s)"` → 4;
  `"Error: Authentication failed …"` → undefined.

New test names (all in `test/adapters.test.ts` under
`parseCopilotRequestCount (P3/D5)`):
1. `extracts N=1 from a real short Copilot session`
2. `extracts N=1 from a real multi-tool-use Copilot session (billing-accurate)`
3. `extracts N=4 from a multi-premium-request fixture`
4. `returns undefined when the Requests line is absent (auth failure)`
5. `returns undefined for empty input`
6. `handles large two-digit counts`
7. `handles zero request count without collapsing to undefined`

Fixtures committed at
[`test/fixtures/transcripts/`](../test/fixtures/transcripts/).

Proof of the fix on a rerun of `demo-fast`:
[`docs/debug/demo-runs/p3-proof.log`](debug/demo-runs/p3-proof.log) +

## 9. Unresolved

### 9a. Live PAT in git history (before redaction)

Commit `5309883` committed `docs/debug/env-fail.json` with the live
`GITHUB_TOKEN` value still in it. The subsequent commit `06475a8` redacted
the working-tree copy, but the original blob remains reachable via
`git show 5309883:docs/debug/env-fail.json`. **The user should rotate
that PAT out of band.** I did not do a history rewrite because it is
destructive and the PAT is narrow-scoped (no Copilot Requests permission
— that's the entire reason the P0 bug manifested). Proposed next step:
user regenerates the PAT on github.com, updates `.env`, then decides
whether to do a `git filter-repo` rewrite before pushing.

### 9b. Claude Code premium-request count remains `undefined`

The P3 fix is complete for Copilot. Claude Code `-p` mode does not expose
a stable per-session premium-request marker on stdout or stderr, so
`parseRequestCount` in `claude-code-adapter.ts` intentionally returns
`undefined` rather than fabricate a count. Proposed next step: either
hook into Anthropic's billing API (adds a network dep + API key
requirement) or count `Assistant:` response boundaries with a more
permissive regex once `claude -p` output format stabilizes. Documented
in both `docs/benchmarks.md` and `benchmarks/README.md` D5 notes.

of Copilot time. The `run_fresh.sh` producers (ORCHESTRATOR / SINGLE_SHOT
/ LADDER) remain at their own schedule in the existing harness. Proposed
next step: add a second `run-n.sh` cycle for `api-quick` at N=5, commit
alongside a second entry in `statistical_summary.md`.
