# Verification

This page describes what runs in production today and what exists as v7 verification library code.

## Production path today

The active per-step verifier is `src/verifier-engine.ts`. It runs after an agent step writes a transcript to `steps/step-N/share.md` and before that step branch is accepted.

For each step, the verifier:

- Parses the `/share` transcript with `src/share-parser.ts`.
- Checks transcript claims for tests, builds, commits, changed files, and unsupported claims.
- Cross-references hook-recorded file evidence when a hook evidence log is present.
- Runs outcome checks against the worktree when the caller provides worktree info.
- Writes `verification/step-N-verification.md`.

Required checks must pass for the step verifier to pass. Optional claim checks can fail without failing the step, but they are recorded as unverified claims.

## Outcome checks

Outcome checks live in `src/verifier/outcome-checks.ts`.

| Check | Required | What it does |
| --- | --- | --- |
| `git_diff` | Yes | Confirms committed or uncommitted work exists relative to the step base SHA. If no diff exists but build or tests pass, the check is downgraded for idempotent work. |
| `file_existence` | Yes when expected files are supplied | Confirms expected files exist in the step worktree. |
| `build_exec` | Yes when a build command is detected | Runs `npm run build` or `make build`. |
| `test_exec` | Yes when a test command is detected | Runs `npm test`, `make test`, or an isolated pytest command. Set `SWARM_SKIP_OUTCOME_TEST_EXEC=1` to skip this outcome path. |

The pytest command is scoped with `--rootdir` and ignores orchestrator artifact directories so nested `runs/` and `.swarm/` trees are not collected as tests.

## Transcript checks

Transcript checks live in `src/verifier/transcript-checks.ts`.

| Check | Required | What it does |
| --- | --- | --- |
| `test` | Configured per step | Confirms the transcript includes a test command and output. |
| `build` | Configured per step | Confirms the transcript includes a build command and success evidence. |
| `commit` | Configured per step | Confirms the transcript includes git commit evidence. |
| `claim` | Optional unless hook evidence contradicts the transcript | Records claims that were not backed by transcript evidence. |

When outcome execution checks are present, transcript-parsed test and build checks are demoted to optional. Real execution evidence wins over transcript-only evidence.

## Hook evidence

Hook evidence is generated by `src/hook-generator.ts` when hooks are enabled. The verifier can read the hook JSONL log and compare it with the transcript.

Hook evidence can fail a step when it records a scope violation or records errors that the transcript does not acknowledge. It also records files seen by hooks but omitted from the transcript as optional evidence.

## Final quality gates

After the step loop and branch merges, `src/quality-gates/` runs a 9-gate advisory report against the merged result. Reports are written to:

```text
<runDir>/quality-gates/quality-gates.md
<runDir>/quality-gates/quality-gates.json
```

Gate findings do not block branch merges today. The runner returns an advisory result and writes failed gate statuses into the report. Downstream CI wrappers can still decide to treat failed gate statuses as a failed job after the merge has happened.

See [quality-gates.md](quality-gates.md) for gate details.

## v7 falsification battery

The v7 battery exists as library code under `src/verification/`. It is not wired into the automatic per-step run loop yet.

| Layer | Source | Status | What it checks |
| --- | --- | --- | --- |
| Test synthesis | `src/verification/test-synthesizer.ts` | Library code | Asks an agent adapter to generate a regression test that fails against the base repo. |
| Differential gate | `src/verification/differential-gate.ts` | Library code | Runs the same test command against the base commit and the agent branch. The test must fail at base and pass at patch. |
| Mutation gate | `src/verification/mutation-gate.ts` | Library code | Runs mutation tooling for changed JavaScript, TypeScript, Python, or Java files and compares the mutation score to thresholds. |
| Cheat detector | `src/verification/cheat-detector.ts` | Library code | Scans diffs for hardcoded answers, swallowed exceptions, unauthorized test edits, mock-only changes, and complexity mismatch. Optional Semgrep support exists when rules are present. |
| Property gate | `src/verification/property-gate.ts` | Library code | Generates fast-check, tsx, node, or Hypothesis harnesses for modified functions and reports counterexamples as advisory findings. |
| Attestation | `src/verification/attestation.ts` | Library code plus one CLI verifier | Creates and verifies signed in-toto SLSA v1.0 provenance envelopes attached as git notes. |
| Composite score | `src/verification/composite-score.ts` | Library code | Combines cheat-detector, property-gate, attestation, and advisory gate scores into a human-review decision. |

The only v7 battery command exposed through the shipped CLI today is:

```bash
swarm attest verify <commit>
```

Automatic per-step test synthesis, differential verification, mutation testing, property checks, composite scoring, and attestation generation are still integration work.

## Attestation details

Attestation code lives in `src/verification/attestation.ts` and `src/verification/cosign-attestation.ts`.

The envelope records:

- Subject git commit SHA.
- Goal hash.
- Plan hash.
- Agent tool, version, and model.
- Transcript hash.
- Layer results.
- Composite score.
- Timestamp.

`generateSignedAttestation` signs with cosign keyless by default. `attachAttestationNote` writes the signed payload under `refs/notes/swarm-attestation`. `verifyAttestation` reads that note, checks that the subject commit matches, and verifies the signature. Test-only unsigned attestations are accepted only when their deterministic test signature matches the envelope.

## Configuration

The v7 library reads verification thresholds from `.swarm/gates.yaml`.

```yaml
verification:
  mutation:
    failBelow: 0.6
    warnBelow: 0.8
  composite:
    threshold: 0.7
    weights:
      cheatDetector: 0.4
      propertyGate: 0.4
      attestation: 0.2
    advisoryGatePenalty: 0.02
```

The production evidence verifier does not read these v7 thresholds yet.
