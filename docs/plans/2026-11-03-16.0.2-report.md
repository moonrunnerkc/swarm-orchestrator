## 2. The platform fix

**Cause.** The prompt never named the machine. Models wrote GNU `sed -i 's/a/b/' file`. On macOS,
BSD `sed` takes the script as the backup suffix and fails, so every in-place edit in the dossier
and t6 runs failed. The loop's only action was the shell.

**Change.** At session start the shell and environment the commands get probe the machine once:
- the system and `/bin/sh`;
- the GNU, BSD, BusyBox or mawk flavor of `sed`, `grep`, `find`, `awk` and `xargs`, read from the
  version line, or from a behavior only one form has;
- the programs and container runtimes on PATH;
- where the checks run, and the repository root.

The block is bounded at 4,000 bytes, recorded in the session-started ledger record, and covered by
`promptSha256`. Edit and write blocks go through the chokepoint's new `edit` under the same path
policy. Their removal condition is in DECISIONS.
