## Verifier findings for a fix (evidence)

**A. False regression from check order plus a base control that keeps ignored build output (depose#4).**
- Evidence: in `report.json` of run 36652113675, `typecheck` has `observation.exitCode: 1`, `stdout: ""`, `stderr: ""`, `durationMs: 3871`. Its `baseObservation.exitCode` is 0 (`durationMs: 4456`), and it carries `attribution: "new"`. The patch changes only depose's swarm-verify workflow file.
- Cause: `src/gates/node-gates.ts` orders checks `typecheck, lint, format, build, tests`. The 1.2.0 fix moved build ahead of tests but not ahead of typecheck. depose's `typecheck` is `pnpm -r run typecheck`, where each package runs `tsc --noEmit` and resolves workspace dependencies through `dist/index.d.ts` (the package.json `types` and `exports`). Only the `build` step (`tsc --build && ...`) produces those files, and the project's CI runs `pnpm build` before `pnpm typecheck`.
- Why the base passes: `resetToBase` in `src/gates/independent-verification.ts` runs `git checkout --force --detach <base>` and then `git clean -fdq`. That keeps ignored files, and `dist/` is in `.gitignore`. So the base control's typecheck runs against the `dist/` the head's build left behind. Head and base are measured under different conditions, and a workflow-only patch reads Regression: fail.
- Possible fixes: run build before typecheck as well as before tests, or measure the base without the head's ignored build outputs, or both.
- Secondary: the failed check records no output at all. It is probably `npm run --silent` passing `npm_config_loglevel=silent` into `pnpm -r`, which then prints nothing. This is not proven here.

**B. Inherited failures read as unmeasured because a random temp path is part of the compared cause (tracemantle#16).**
- Evidence: in run 36652116619, the head and base failing sets are identical: the same 3 ids, `outputTruncated: false` on both runs. The `test_build_plan_core` messages are equal. Both `test_pre_commit` messages differ only in a temp directory name inside pre-commit's error (`...eponyx5xidu` at head, `...epoc90ac5y6` at base).
- Cause: `attributeFailure` in `src/gates/failure-attribution.ts` sets `causeChanged` when any `patched.causes[id] !== base.causes[id]`. `normalizedCause` sets aside colours, timestamps and durations, but not temporary paths.
- Result: `attribution: "unattributed"`, and the regression dimension is unmeasured.
- The advice text is also wrong for this case: it says "Its output names no tests to compare", but the output names all three.

**C. A real regression read Incomplete when the base control's worker crashed (quantproof red control, attempt 1 of run 36652995077).**
- Evidence: the base run's JSON reports `numFailedTests: 0` and `success: true`, but the process exits 1. stderr shows a native abort at worker exit inside better-sqlite3 on Node 24: `node::RemoveEnvironmentCleanupHook ... Assertion failed: (env) != nullptr` from `Statement::~Statement()` in `better_sqlite3.node`.

- The verdict was "the base fails it too, but the failures cannot be matched one to one", so regression unmeasured, where the correct reading is fail. It is conservative, not a false pass.
