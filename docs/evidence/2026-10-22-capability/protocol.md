# Local development trial registration

Frozen before task inference. Product revision is the commit containing this protocol; its build
will be copied to an immutable cache directory and its tree digest recorded before launch.
Only local compute is authorized. No paid inference, remote model, model download or server restart.

Hypothesis: early static feedback within a repair can turn an otherwise rejected useful candidate
into a complete delivered artifact within the same total allowance. This is development material,
not generalization. Mocha and entities were previously exposed.

Record local content IDs, server version and hardware before launching. Models run sequentially.
No claim about the products' normal frontier-model configurations follows from local-model runs.
OpenCode's current stable npm version was queried before installation in a separate tool cache.
Neutral edit-and-test smoke tests must precede competitor task runs. A broken comparator setup
is infrastructure failure, never a Swarm win. Launch competitors regardless of Swarm results.

## Frozen work and resources

Reuse the exact task, visible checks, base and hidden scorers from the October 22 stage for
entities and its October 21 alias task for Mocha. The Mocha driver scripts only the retained faulty
first candidate; subsequent model calls are live. Both Swarm arms use the same revised binary;
only `--repair-finish` differs. No repair trace flag. No worker sees hidden checks or results.
All task deliverables, immutable paths and change policies are identical across arms.

Nine minutes per launch including product verification, eight million total reported tokens as
a safety ceiling, 40 steps per Swarm loop and three attempts. Every additional continuation is
charged to the original allowance. Existing command runner kill grace is cleanup, not useful
work. At most eight launches, 72 agent-minutes, plus at most six minutes neutral smoke inference;
expected local runtime 60 to 100 minutes including preparation/scoring, $0 paid inference.
No other inference or heavy test suite during a launch. No retries for favorable scores.
Infrastructure failures consume their slot; fix only to enable a different registered slot and
record a dated amendment before proceeding. Unusable second-model readiness remains unmeasured.

## Scoring and decision

Score each exact delivered patch independently using the frozen visible, hidden and project
checks and the expanded alias preservation check. Report lint and formatting alongside semantic
correctness; all required checks must pass for a complete delivery in this study. Preserve the
older study's different historical rubric. Added tests must fail on base source and pass on the
candidate. No weakening assertions or acceptance criteria. Hidden cases and faulty/reference
controls are inherited from the validated stage and remain outside worker checkouts until scoring.

Record initial and delivered patches, finish notice, failed checks, whether a continuation ran,
subsequent edits, full gate outcomes and rollback. A notice without a changed decision is not an
evaluation of the intended mechanism. Report wall, model time, tool time, verification intervals,
usage including unknowns, and human intervention. Timing categories may overlap.

Keep experimental unless enabled wins complete delivery over disabled at matched resources,
with no semantic damage. A single paired win is narrow evidence, not broad superiority. Report
all pairs, ties, losses and failed starts. With only two task families and single samples, report
counts and avoid significance claims. No simple-agent baseline is implemented in this trial;
product comparisons cannot establish the value of orchestration alone.
