# Calibration report, 2026-09-04

Two sweeps of the 20-case golden set on this machine, three repeats per case, on the Ollama
backend, run from the CLI built at commit `710e63b4` of this pass, with the sampling pinned on
the wire and in every model-call record. This is the current measurement of this machine and
supersedes `../2026-09-02/calibration-report.md`, which stays as the record of what was true
then. Every number below is read from the `calibration-run` records of the bundles beside this
file by `../../../scripts/compare-calibrations.mjs`, and every comparison with September 2 is
between two distributions, never between two numbers.

## Trust condition

The pass that produced this report closed the empty-turn defect one level further than
2026-09-02 had: a repeat the runtime cut short after the model had answered no longer has its
gate run and scored (`../../empty-turn-diagnosis.md`, and the pass's state file). So the
check on these bundles is exact. Every `model-call` record carries the harness's verdict on
whether the turn held anything, every `calibration-run` record says whether its gate was
measured, and nothing a runtime dropped reaches a score.

| gemma4-mistral | 604 | 9 | four on `gemma4:31b`: two output caps spent on nothing at steps 6 and 7 of one repeat, sampled again and then measured; two calls aborted by the sweep's own five-minute repeat budget, ending two repeats of `pass2-tautology-line-split` as `max-wall-time`, executed and measured as failures with 8 and 7 answered turns. Five on `mistral-small3.2:24b`: finish reason `stop`, 39 to 235 output tokens counted, no text and no tool call delivered, each ending its repeat as `empty-response` |

The five mistral turns are a shape August did not have: the backend reports tokens generated
and delivers nothing. Their repeats had answered before, so they stand as executed, and their
gate was not run, which the report prints as `cut short before the gate` rather than as red.
They were not sampled again: the retry that samples an empty turn once more landed in this
tree (`96df15dc`) after these sweeps had started, from the CLI built two commits earlier. The
sweep is kept rather than rerun, because a rerun would measure the retry and not the model,
and what it measures is stated here.

The machine was not idle during the pair sweep: this pass's own test suite ran on it eleven
times, about a minute each, while the sweep ran. That shows in the pair sweep's wall time and
first-token spread, not in gate outcomes, and the sweep before it ran on an idle machine.

## What this does and does not support

Two models measured twice, two days apart, on the same cases with the same sampling, agree to
within their own spreads on every dimension, and the third is refused on both days by the same
floor. That is what a repeatable measurement of this machine looks like, and it is all this
report claims. Nothing here compares a model to another tool, nothing is a benchmark, and the
numbers are one machine's.
